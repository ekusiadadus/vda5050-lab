# Dependency and supply-chain inventory

Snapshot date: 2026-08-07.

`Cargo.lock` is committed for reproducible application builds. CI uses
`--locked`, Rust 1.97.1, minimal GitHub permissions, and a full-SHA pin for
`actions/checkout`. A release must not be cut when the lockfile differs from
the reviewed dependency graph.

The distributed `vda5050-doctor` dependency graph contains no HTTP, MQTT,
socket, telemetry, database, XML, or archive client. That executable retains no
network path. The workspace-wide graph no longer has that property:
`vda5050-demo` deliberately uses `rumqttc` with default features disabled and
its asynchronous socket dependencies to talk to the plaintext disposable Tier
1 broker. TLS is out of scope for this isolated harness. The demo binary is not
included in any Doctor archive and cannot add a network path to Doctor merely by
sharing the workspace. Both scoped statements must be rechecked whenever
`Cargo.lock` changes.

## Demo and release-only tools

The Tier 1 harness uses Docker Compose, the digest-pinned
`eclipse-mosquitto:2.1.2-alpine` image recorded in `compose.yaml`, and
digest-pinned Rust 1.97.1 builder and Debian Bookworm runtime images recorded in
`demo/Dockerfile`. The release media suite is generated by
`scripts/render-demo-video.sh` through
`make demo-video RELEASE_TAG=vX.Y.Z`; it runs the fixed 1, 2, 5, 10, 50, and
100-robot traces, renders one MP4 and GIF per scale, and creates MP4/GIF overview
media. These fourteen outputs are generated media and are not committed to Git.

Video generation also requires the GitHub-hosted runner's Docker Compose,
`jq`, FFmpeg/`ffprobe`, ImageMagick, and a known DejaVu or SF system font. Their
versions are checked for presence and recorded by the hosted environment, but
are not locked in `Cargo.lock` or described by the Doctor CycloneDX SBOM. The
Ubuntu release runner also installs `librsvg2-bin`: its ImageMagick 6 package
delegates the renderer's SVG-to-PNG conversion to `rsvg-convert`. The release
workflow verifies that command before running the media suite. The
renderer verifies each observed D4 result, exact robot count, trace/report
digest binding, payload-coordinate input, per-scale 1280x720 dimensions, and an
eight-second duration. The 1920x1080 overview is composed only from those six
verified videos. The project therefore attests the generated
bytes and source workflow without claiming byte-for-byte reproducible video
encoding across runner-image revisions.

The MP4 and GIF files are release payloads, not Rust dependencies. Release
assembly accepts only the twelve fixed scale names and two overview names,
rejects symlinks and unexpected files, enforces format signatures plus 100 MiB
MP4 and 50 MiB GIF ceilings, and includes every byte in `SHA256SUMS` and the
default SLSA attestation. The CycloneDX SBOM remains scoped
to the `vda5050-doctor` binary and is attested only against its four native
archives. This distinction prevents an SBOM for one product from being presented
as dependency evidence for generated media.

## Verification

Run the local quality and advisory gates:

```sh
make ci
cargo install cargo-audit --version 0.22.2 --locked
cargo install cargo-deny --version 0.20.2 --locked
make audit
make deny
```

The 2026-08-07 audit used `cargo-audit 0.22.2`, loaded 1,190 RustSec
advisories, scanned 111 locked crate packages, and reported no known
vulnerability. This is a point-in-time result, not a guarantee about future
advisories.

The release policy also evaluates advisories, bans, licenses, and sources for
all four distributed targets with `cargo-deny 0.20.2`. Only Apache-2.0,
Apache-2.0 WITH LLVM-exception, MIT, and Unicode-3.0 were required by the
locked graph; unknown registries, Git dependencies, and wildcard requirements
are denied.

## Change policy

Every dependency change must include:

1. a reviewed `Cargo.toml` and `Cargo.lock` diff;
2. `cargo tree --workspace --edges normal --locked` review;
3. formatting, strict Clippy, and locked workspace tests;
4. a fresh RustSec audit;
5. confirmation that the offline Doctor executable gained no network-capable
   path, with demo-only network dependencies reviewed separately;
6. license review for every new direct dependency; and
7. an update to this inventory when resolved direct versions change.

Tagged releases enforce line and region coverage floors with pinned
`cargo-llvm-cov 0.8.7` for Doctor and its supporting libraries. The active demo
crate is excluded from that source-coverage denominator and instead passes the
mandatory disposable-broker E2E and verdict-matrix gates. Releases then generate
a binary-scoped CycloneDX 1.5 SBOM with
pinned `cargo-cyclonedx 0.5.9`. GitHub Actions creates Sigstore-backed SLSA build
provenance and SBOM attestations with the official `actions/attest` action
pinned to a full commit SHA. Users must still verify the downloaded archive,
checksum, and attestation rather than trusting the release page alone.
